# Quality check, 2026-11-01

The ten engineering rules, checked against the code on `main`, with the evidence. Run on Windows 11
with Python 3.14, DuckDB 1.5.6 and SQLite.

| # | Rule | Status | Evidence |
|---|---|---|---|
| 1 | Assume every call can fail | pass | The external calls are DuckDB and SQLite connections and one subprocess. SQLite connects with `timeout=10.0` (`engines.py`). The bench subprocess has `timeout=600` (`bench.py`). DuckDB is in-process and capped by `threads` and `memory_limit`. Every `except` either re-raises after rolling back (`demo.py`, `ledger.py`, `runner.py`) or converts the error to `EngineError`/`SpecError`, and the CLI reports those with exit 1. `table_exists` treats `EngineError` as "absent" on purpose. No retries, so nothing to bound. |
| 2 | Writes safe to retry | pass | This is the repo's purpose. Each partition is one transaction holding the data write and the ledger row. MERGE, atomic overwrite and dedup insert are each checked by first-run/rerun/crash tests on both engines (`test_patterns.py`, `test_crash.py`, `test_randomized.py`), and `ibk bench` reports 82 scenarios with 0 defects. The CLI `--json` bench report is written in place, but it is a derived file that a rerun rewrites. |
| 3 | No race conditions | pass | One connection per run, single-threaded. Concurrency between processes is left to the engine's transactions; killed processes are covered by `test_crash.py`. |
| 4 | Don't trust the clock | pass | Bench durations use `time.perf_counter`. Ledger timestamps are `datetime.now(UTC)` with microseconds. `ORDER BY started_at` / `committed_at` in `ledger.py` orders the `ibk status` display only. Resume decisions use the set of committed partitions and `max(watermark_high)`, a data watermark rather than the clock. |
| 5 | Read before changing | pass | No environment variables are read. Every path in the README exists. |
| 6 | Never break compatibility | pass | No schema or format changed in this pass. |
| 7 | One source of truth | pass | The ledger tables `ibk_runs` and `ibk_partition_commits` are the single record of what was committed. Versions are pinned in `constraints.txt`. |
| 8 | Small changes, no secrets, validate input | pass | The secret grep found nothing. Partitions must be strict `YYYY-MM-DD` calendar dates, unique, and at most 10,000 per run. Identifiers are checked against a pattern and quoted. Job specs are schema-checked (`test_spec.py`). |
| 9 | Tests that can actually fail | fixed | No `skip`/`xfail` and no tautologies (`pytest -rs` reports 0 skipped). Mutation check: 11 of 12 killed; the survivor now has a test. |
| 10 | Re-verify | pass | `ruff check` clean, `ruff format --check`: 32 files already formatted, `mypy --strict`: no issues in 23 files, `pytest`: 182 passed, `pip-audit`: no known vulnerabilities (after upgrading the venv's bundled pip 26.1.1, which `make setup` also does), `audit_repo.py`: OK. |
